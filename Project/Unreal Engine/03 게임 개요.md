# 게임 개요

## 컨셉
- 겜바바 팩: 인디 게임 '던전 앤 스톤' 속 바바리안이 된 주인공의 시점으로 원작 스토리를 따라가는 HD-2D 그리드 전술 RPG
- 오리지널 팩(공개·시험용): 같은 시스템에 이름과 데이터만 다른 미궁 도시 전술 RPG
- 장르: 싱글플레이 그리드 전술 RPG. 레퍼런스: 트라이앵글 스트래티지(HD-2D 전술), 유니콘 오버로드(부대·자동 전투), 파이널 판타지 택틱스(CT 턴 순서)
- 볼륨: 정해진 상한 없음. 스토리 매핑 후 판단 (아래 '볼륨 체크')
- 시점: 주인공 단일 시점. 동료 시점 에피소드(메이플스토리 DS식)는 후속작이나 DLC 아이디어로 보류

## 3층 구조
원작 스토리를 최대한 따라가면서도, 판권 전에는 IP 없이 개발하기 위한 구조.

| 층 | 내용 | IP | 시점 |
| --- | --- | --- | --- |
| 1. 시스템 | 전투 규칙, 턴 순서, 성장(능력 흡수·슬롯), 원정 주기, 마을 기능, 이벤트·대화 엔진, 저장 | 없음 | 지금 설계, 2028~ 구현 |
| 2. 콘텐츠 데이터 | 유닛, 몬스터, 능력 목록, 아이템, 맵, 대사 | 팩마다 다름 | 오리지널 팩 먼저, 겜바바 팩은 판권 후 |
| 3. 스토리 | 챕터 구성, 이벤트 순서, 연출 | 겜바바 팩 | 매핑 문서는 지금, 구현은 판권 후 |

- 코드에는 IP 이름을 하나도 넣지 않는다. 이름·수치·목록은 전부 데이터
- 겜바바 스토리 매핑을 먼저 해두면, 스토리에 필요한 시스템(클랜 단위 전투, 항해 등)을 처음부터 설계에 넣을 수 있다
- 원작 세계 자체가 '게임'이라 규칙이 이미 게임 디자인에 가깝다 (레벨 = 정수 칸, 종별 첫 처치 경험치, 월간 미궁 + 층별 체류 기간) → 시스템 층으로 옮기기 좋다

## 핵심 루프
1. 마을에서 준비: 정수 흡수, 장비, 보급, 동료 관리
2. 미궁 원정: 월 1회 개방 → 층에 진입 → 노드를 이동하며 전투·이벤트·채집
3. 귀환: 층이 닫힐 때 강제 귀환. 조기 탈출이 안 되므로 보급과 체력이 원정 내내 이어지는 자원
4. 성장: 새 몬스터 첫 처치로 경험치 → 레벨업 → 정수 칸 증가 → 정수 확보가 다음 병목
5. 스토리 진행 → 다음 달 원정

## 범위: 2페이즈 구성
- 원작을 최대한 다 담는다
- 1페이즈: 원작 '지하' 이전까지의 이야기 (약 500~600화)
	- 주인공이 과거로 넘어가는 시점 앞에서 한 번 더 나누는 안 검토 (1페이즈 전반·후반)
- 2페이즈: 노아르크와의 전쟁
- 원작의 규모 확장(파티 → 팀 → 클랜)과 맞추면 시스템 해금 순서가 자연스럽다

### 볼륨 체크 (미정)
- 1페이즈가 원작 몇 화까지인지, '지하' 구간(지하 1층, 기록보관소)은 어느 페이즈에 넣을지 확인
- 플레이타임 상한은 없음. 다만 출시 단위가 너무 크면 2인 팀이 끝내기 어려우므로, 과거로 넘어가는 시점 등에서 나눠 출시하는 안을 검토
- [[03-3 세계·미궁·스토리]]의 스토리 매핑을 채우면서 판단

## 이전 초안([[Unreal Engine(HD-2D)]]) 정리 원칙
- 겜바바 규칙을 기준으로 삼고, 초안 요소는 호환되면 유지, 충돌하면 보류
- 유지 후보: 장비 등급·무게·내구도, 마을 시설(상점·대장간·수리점·경매장·선술집·도서관), 미궁이 닫힐 때 귀환, 시간 넘기기
- 충돌: 레벨 없음·훈련 성장(원작은 레벨 = 정수 칸), 아카데미 스킬 학습(원작은 정수로 스킬 획득), 선술집 무작위 동료(원작은 스토리 동료), 시크릿 장비(원작 넘버즈와 역할 겹침)
- 보류: 현실↔게임 왕복, 할아버지 악마·0층·회귀 스토리 → 오리지널 팩 세계관 후보 ([[03-3 세계·미궁·스토리]])
