# 아트·머티리얼

## 문제
- 2인 모두 개발자, 디자인 경험 없음 → 그래픽이 가장 큰 병목 (2025년 중단 이유)
- 이전 시도: TRELLIS.2(이미지 → 3D)를 연구실 5070 Ti에서 로컬로 돌리다 그래픽 쪽 문제 발생

## 관점
- HD-2D의 인상은 상당 부분 렌더링(조명, 포스트 프로세스, 머티리얼)에서 나온다 → 개발자가 다룰 수 있는 영역
- 그림 부담이 몰리는 곳: 캐릭터 스프라이트(애니메이션), 환경 텍스처·소품
- 이미지 → 3D 생성은 촘촘한 메시에 픽셀 격자와 안 맞는 텍스처를 뽑아서, 각진 단순 형태 + 또렷한 픽셀 텍스처인 HD-2D와 결이 다름 → 리토폴로지·텍스처 재작업 부담. 환경은 단순 모듈 + 픽셀 텍스처가 맞음

## 파이프라인 (안)
1. 아트 방향·스타일 가이드: 기준 게임, 팔레트, 캐릭터 비율, 스프라이트 크기, 방향 수, 애니메이션 목록
2. 환경: 언리얼 모델링 모드나 Blender로 단순 모듈(벽·바닥·계단·지붕) → 반복되는 픽셀 텍스처
3. 캐릭터: AI 픽셀 스프라이트 도구로 초안 → Aseprite에서 정리(외곽선, 팔레트, 프레임 보정)
4. 이펙트: 나이아가라 + 픽셀 플립북
5. 룩 마무리: 스프라이트 조명 반응·그림자, 틸트시프트 심도, 블룸, 안개, 색 보정

## AI 도구 메모 (2026, 비교 글 기준이라 직접 확인 필요)
| 도구 | 특징 | 가격 |
| --- | --- | --- |
| PixelLab | 4/8방향 회전, 뼈대 기반 애니메이션, 타일셋, Aseprite 플러그인·API | 월 12달러부터 |
| Retro Diffusion | 픽셀 격자 출력, 애니메이션, 타일셋, Aseprite 안에서 동작 | 일회성 20/65달러 |

- 공통 한계: 프레임 사이 일관성(비율·색·디테일이 흔들림), 팔레트 정리와 외곽선은 수작업
- 클라우드 도구는 로컬 GPU 부담이 없음

## 주의
- Steam (2026-01 개정): 게임에 들어간 AI 생성 콘텐츠(아트, 사운드, 텍스트 등)는 신고하고 스토어 페이지에 사용 방식을 적어야 함. 개발 효율용 AI(코딩 도우미 등)는 대상 아님
- 웹툰·웹소설 쪽은 AI 그림에 민감한 편 → 판권 피칭용 대표 캐릭터 이미지는 사람이 다듬은 결과물로
- AI 결과물의 권리 문제 → [[02 IP·판권]] 법률 자문 항목

## 만들 머티리얼
- 스프라이트: 조명 반응, 그림자, 피격 번쩍임, 외곽선
- 환경: 픽셀 텍스처 설정(필터 Nearest, 압축 끄기), 물, 수정 발광
- 포스트 프로세스: 틸트시프트 심도, 블룸, 비네팅, 색 보정
- 가림 처리: 가리는 오브젝트 디더링 반투명, 가려진 유닛 실루엣 (커스텀 뎁스 + 포스트 프로세스)
