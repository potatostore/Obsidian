# 🔮 회원님 맞춤형 Obsidian 작성 규칙 (Formatting Rules)

이 파일은 에이전트가 회원님의 기존 작성 습관(Style)을 학습하여 **자동으로 추출한 고유 규칙 정의서**입니다.
이 룰셋을 바탕으로 규격에서 벗어난 "아웃라이어(Outlier)" 노트들을 탐색하고 안전하게 교정합니다.

---

## 🏁 1. 제목 문법 규칙 (Heading Rules)

*   **규칙 ID**: `RULE_HEADING_SPACE`
    *   **설명**: `#`, `##` 등 제목 표시용 샵 뒤에 공백이 없는 오류(예: `#1. 개요`)를 자동으로 감지해 공백을 추가(`# 1. 개요`)합니다. 
    *   **주의**: `#대제목`이나 `#단어`처럼 뒤에 공백이 전혀 없고 본문에 단독으로 적혀 검색 태그로 동작하는 해시태그는 절대 건드리지 않고 원본을 안전하게 보호합니다.
    *   **상태**: `[Enabled]`

---

## 🏁 2. 메타데이터 필수 규칙 (Metadata Rules)

*   **규칙 ID**: `RULE_REQUIRED_FRONTMATTER`
    *   **설명**: 모든 지식 노트 상단에 회원님이 가장 자주 쓰시는 필수 YAML Frontmatter 규격을 확보합니다.
    *   **회원님 보관소 맞춤형 필수 항목**:
        - `tags`: 회원님의 빈출 메타데이터
        - `aliases`: 회원님의 빈출 메타데이터
        - `created`: 회원님의 빈출 메타데이터
    *   **기본 주입 항목**:
        *   `tags`: 누락 시 `[seed]` 자동 주입
        *   `aliases`: 누락 시 `[]` 자동 주입
        *   `created`: 누락 시 파일 최초 작성일(`YYYY-MM-DD`) 자동 주입
    *   **상태**: `[Enabled]`

## 🏁 3. 하이라이트 문법 규칙 (Highlight Rules)

*   **규칙 ID**: `RULE_HIGHLIGHT_SPACES`
    *   **설명**: 하이라이트 표시 기호(`==`) 내부 양끝의 공백을 제거하여 렌더링 오차를 방지합니다.
    *   **작동 예시**: `== 하이라이트 ==` ➡️ `==하이라이트==`
    *   **상태**: `[Enabled]`

---

## 🏁 4. 교과서식 구조 계층 규칙 (Textbook Hierarchy Rules)

*   **규칙 ID**: `RULE_TEXTBOOK_HIERARCHY`
*   **업데이트**: 2026-08-14 — 회원님이 대학교 수업 내용을 교재처럼 정리하고 싶다는 목표를 알려주셔서, 4단계 계층 모델로 구체화함.
    *   **설명**: 지식/강의 노트가 실제 교재의 목차처럼 **[대단원] → [중단원] → [소단원] → [개념단위]** 4단계로 유기적이고 일관되게 구성되도록 강제합니다. 이 규칙은 파이썬 스크립트가 아니라 정리를 요청받은 에이전트(Claude)가 노트를 재구성할 때 직접 참고합니다.
    *   **계층 모델**:
        1. **대단원 (`# `)**: 과목/전체 주제 단위의 최상위 챕터 (예: `# 1. 운영체제`)
        2. **중단원 (`## `)**: 대단원을 이루는 핵심 섹션 (예: `## 프로세스 관리`)
        3. **소단원 (`### `)**: 중단원을 쪼갠 하위 주제 (예: `### 프로세스 스케줄링`)
        4. **개념단위 (`#### `)**: 실제로 설명되는 가장 작은 낱개 개념. 소단원을 구성하는 최소 단위이며, 반드시 헤딩 그 자체로 존재해야 함 (예: `#### FCFS 스케줄링`)
        5. **본문 설명 (Plain Text / Bullet)**: 각 `개념단위(####)` 헤딩 바로 아래에는 텅 빈 공간이 아닌 해당 개념을 충실히 설명하는 글, 불릿 목록, 하이라이트 혹은 코드 블록이 반드시 포함되어야 함
    *   **정리 시 적용 방법**: 회원님이 "이 메모 정리해줘"라고 요청하면, 이 파일을 먼저 읽고 본문 내용을 의미 단위로 쪼개어 위 4단계(대단원/중단원/소단원/개념단위) 헤딩 구조로 재배치한 뒤, 각 개념단위 아래에 기존 설명을 정리해서 배치함. 기존에 있던 정보(코드블록, 링크, 하이라이트, 표 등)는 삭제하지 않고 알맞은 계층 아래로 옮기는 것을 원칙으로 함.
    *   **적용 범위**: 전공/강의 지식 노트(`University`, `Computer Science`, `Algorithm`, `Data Structure`, `Language`, `Frameworks & services` 등)에 우선 적용. `-Calendar-`(일별 TODO/일지)처럼 시간순 기록용 노트는 이 계층 구조를 강제하지 않음 — 그런 노트를 정리해달라고 명시적으로 요청받은 경우에만 판단해서 적용.
    *   **자동 감지 및 아웃라이어 경고 대상**:
        *   **계층 건너뜀 (Hierarchy Skip)**: 대단원(`#`) → 중단원(`##`) → 소단원(`###`) → 개념단위(`####`) 순서 중 한 단계를 건너뛰고 등장하는 경우 (예: `#` 다음에 바로 `###`)
        *   **상위 단원 누락 (Missing Parent Head)**: 메모가 최상위 대단원(`#`) 없이 중단원(`##`) 이하로 불쑥 시작하는 경우
        *   **설명 없는 빈 개념단위 (Empty Concept Area)**: `####` 개념단위 제목만 덩그러니 있고 그 아래에 아무런 설명글이나 요약이 없는 경우
    *   **상태**: `[Enabled]`

## 💡 규칙 커스텀 방법
1. 위 규칙의 **상태**를 `[Disabled]`로 수정하면 해당 정리 단계가 건너뛰어집니다.
2. 새로운 문법 변환 규칙이 필요하시다면 이 파일에 새로운 양식을 작성하고 저에게 알려주세요! 그에 맞춰 파이썬 파서를 업데이트해 드리겠습니다.
