# 1장. 컴퓨터그래픽스 개요

## 1. 컴퓨터그래픽스란
- 컴퓨터로 **장면(입력)** 을 처리해 **영상(출력)** 을 만드는 기술
    ⇒ 3차원 그래픽스: 입력이 3D 장면(형상 + 카메라 + 조명), 출력이 2D 이미지
- 한 줄 구조: 장면 데이터 → (렌더링) → 이미지

## 2. 제작 파이프라인 (순서 암기)
| 단계    | 하는 일                   | 산출물            |
| ----- | ---------------------- | -------------- |
| 모델링   | 물체 형상(메시) 제작           | 정점 위치 + 삼각형 연결 |
| 리깅    | 뼈대·관절을 만들어 형상에 연결      | 움직일 수 있는 구조    |
| 애니메이션 | 시간에 따른 포즈·움직임 지정       | 시간별 장면 상태      |
| 렌더링   | 장면(형상·카메라·조명)을 이미지로 계산 | 2D 이미지(픽셀)     |
| 후처리   | 완성된 이미지 보정 (색 보정 등)    | 최종 영상          |
- 렌더링 전 = 3D 장면 데이터 / 렌더링 후 = 2D 픽셀 이미지
- 후처리는 **픽셀을 수정**하는 작업 ⇒ 렌더링 결과가 먼저 있어야 함

## 3. 형상(기하)과 외관 구분
- **형상** = 정점 위치 + 삼각형 연결(메시) ⇒ 실루엣(외곽선)을 결정
- **텍스처** = 면에 입히는 이미지 ⇒ 색(외관)만 바꿈, 삼각형 수·윤곽 불변
    - 벽돌 무늬 텍스처: 돌출돼 보여도 실제 윤곽은 평평
    - 실제로 튀어나오게 하려면 정점 이동 / 삼각형 추가
- 색만 변경 → 텍스처 교체 / 모양 변경 → 정점·삼각형 변경

## 4. 움직임은 어디서 오는가
- **물체의 변형** (리깅 + 애니메이션): 팔이 구부러짐 ⇒ 정점 위치가 변함
- **카메라 변화**: 조각상 주위를 도는 카메라 ⇒ 물체는 그대로, 리깅 불필요
- 영상 = 정지 이미지(프레임)의 시간 순서 나열 ⇒ 매 시각 샘플링한 프레임 필요
- 구분할 것
    - **모핑**: 두 형태 사이를 부드럽게 보간 (외관 변화) ≠ 물리 운동
    - **물리 시뮬레이션**: 중력·충돌로 상태(위치) 계산
    - **렌더링**: 계산된 상태를 이미지로 변환
    ⇒ 상태 계산(시뮬레이션)과 이미지 계산(렌더링)은 별개

## 5. 실시간 vs 비실시간
- 프레임률 공식: f = 1000 / t (f: FPS, t: 프레임당 시간 ms)
- 60 FPS ⇒ t = 1000/60 ≈ **16.67 ms** 이내
    - 20 ms → 50 FPS (미달), 10 ms → 100 FPS (충족)
- **실시간**: 사용자 입력에 즉시 반응, 프레임마다 시간 제한 (게임, 가상 전시)
- **비실시간(오프라인)**: 미리 렌더링 후 재생 (영화, 홍보 영상)
    ⇒ 프레임당 2초가 걸려도 OK: **생성 시간**과 **재생 시간**은 별개
- 주의: 실시간 = 비사실적, 비실시간 = 사실적 이라는 일반화는 **틀림**
    ⇒ 둘의 차이는 시간 제약, 사실성은 기법·자원·목표에 따라 결정
- 응용별 요구: 의료(정확성·신뢰성), 설계 검토(치수 정확성), 게임(일정한 프레임률·반응성)

## 6. 소프트웨어 / 하드웨어 계층
- **모델링 도구**: 형상(메시) 제작·편집
- **게임 엔진**: 장면·로직·렌더링을 통합 관리하는 개발 틀
- **그래픽스 API** (OpenGL ES 등): 응용이 GPU에 그리기를 요청하는 표준 인터페이스
- **GPU**: 정점·픽셀 계산을 병렬 수행하는 하드웨어
- 흐름: 응용이 메시·카메라·조명 데이터를 준비 → API 호출로 전달 → GPU가 그림
    ⇒ API는 명령 인터페이스일 뿐, 장면 데이터를 자동으로 만들어 주지 않음 (응용이 준비)

## 7. AI 기술 동향 (DLSS 등)
- 프레임 생성: 기본 프레임 사이에 AI가 추가 이미지 생성
    - 예) 입력·상태 갱신 40회/s, 기본 1장당 3장 추가 ⇒ 표시 **160 FPS**, 상태 갱신은 **40회/s**
    ⇒ **표시 FPS ≠ 입력·상태 갱신 빈도** (생성된 프레임은 새 입력을 반영하지 않음)
- 평가 축은 따로: 선명도 / 정확성(원본 충실도) / 시간적 일관성 / 속도(지연)
    - 한 프레임이 선명하다고 "항상 정확하고 빠르다"고 할 수 없음
    - 공정 비교: 같은 장면·카메라 경로·해상도·하드웨어 고정 → 프레임 시간, 깜빡임, 재질·조명 보존 관찰
    - 재질·조명이 바뀌어 보이면 선명해도 별도 검토 필요

## 8. 시험 포인트 요약
- 입력(장면) → 출력(영상), 3D인 이유는 입력이 3D 장면이라서
- 파이프라인 5단계 순서와 각 단계의 입·출력 차이
- 텍스처 = 외관 / 정점·삼각형 = 형상
- 움직임의 원인: 변형(리깅) vs 카메라
- FPS 계산: 16.67 ms, 단위(ms vs s) 주의
- 실시간/비실시간 = 시간 제약의 차이 (사실성과 무관)
- API / 엔진 / GPU 역할 구분, 장면 데이터는 응용이 준비
- 표시 FPS ≠ 상태 갱신 빈도, AI 결과는 여러 축으로 평가
- 연습문제 연결: P1-01 ~ P1-10
