# CLAUDE.md — 대학생활 LLM 위키 스키마

> 위치: 볼트의 `.claude/CLAUDE.md` (2026-09-27에 루트에서 옮김). 점 폴더라 Obsidian에는 보이지 않는다.

이 볼트는 **"대학생활"을 주제로 공부한 내용과 경험을 쌓아가는 LLM 위키**다. Karpathy의 LLM Wiki 패턴을 이 볼트에 맞게 구현했다.

- **사람(볼트 주인)**: 무엇을 넣을지 고르고, 질문하고, 방향을 정하고, 의미를 해석한다.
- **LLM**: 요약·링크·허브·인덱스·로그 관리 같은 장부 작업을 전부 맡는다.

작업을 시작할 때 항상 다음 순서로 읽는다.
1. 이 파일
2. `.obsidian-agent/formatting_rules.md` (서식 규칙의 원본)
3. `.wiki/index.md`
4. `.wiki/log.md`의 최근 항목 (`grep "^## \[" .wiki/log.md | tail -5`)

---

## 1. 안전 규칙 (최우선)

1. **삭제·이동은 허락 먼저**: 내용이 있는 파일(노트·이미지·설정)을 삭제·이동·이름 변경·병합하기 전에 반드시 대상 목록을 보여주고 허락받는다. 예외는 git이 스스로 만들고 지우는 잠금·임시 파일, 그리고 LLM이 이번 작업에서 새로 만든 빈 임시 파일뿐이다.
2. **제자리 위키화**: 기존 노트는 그 자리에서 위키 페이지로 전환한다 (2026-09-25 결정).
   - 허용: frontmatter `tags`에 위키 태그 추가, 문서 끝 "위키 연결" 콜아웃 추가·갱신, 본문의 기존 단어를 `[[페이지]]` 또는 `[[페이지|단어]]`로 감싸기, 모순·보충 콜아웃 추가
   - 요청이 있을 때만: 사용자가 쓴 문장을 삭제하거나 다시 쓰는 것, 구조를 재배치하는 것. 구조 재배치는 "정리해줘" 요청이 있을 때 RULE_TEXTBOOK_HIERARCHY에 따라서만 한다.
3. **편집 전 백업**: 기존 노트를 고치기 전에 원본을 `.obsidian-agent/cache/wiki-backup/YYYY-MM-DD/<원래 경로>`에 복사한다 (git 제외 폴더).
4. **git**: 커밋은 Obsidian 종료 시 자동 동기화(`.obsidian-agent/run.sh`, `obsidian_daemon.sh`)에 맡긴다. 직접 커밋해야 하면 macOS에서만 한다. 이 저장소는 `core.precomposeunicode=true`라서 Linux에서 커밋하면 한글 파일명(NFD/NFC)이 중복될 수 있다. 상태 확인은 `git --no-optional-locks status`로 한다.
5. **민감 정보**: `Project/AWS/password.md`처럼 자격 증명이 담긴 노트는 읽지도, 링크하지도, 요약하지도 않는다.
6. **organizer.py 호환**: 본문이나 콜아웃에서 해시(#) 바로 뒤에 글자를 붙여 쓰지 않는다. organizer가 이를 태그로 인식해 frontmatter에 넣는다. 같은 이유로 대괄호 두 개 바로 뒤에 해시를 붙이는 제목 전용 링크도 쓰지 않는다.

## 2. 구조

### 폴더 역할

| 폴더 | 역할 | 유형 태그 |
| --- | --- | --- |
| `Hub/` | 허브(지도) 페이지 | `type/hub` |
| `University/<학기>/` | 수업 노트 = 과목 페이지 | `type/course` |
| `Algorithm/`, `Data Structure/`, `Computer Science/`, `Language/`, `Frameworks & services/` | 개념 페이지 | `type/concept` |
| `Project/` | 프로젝트·활동 (`Project/AWS/`는 클라우드 학습 노트라 개념으로 취급) | `type/project` / `type/concept` |
| `Experience/` | 경험·교훈 (LLM이 일지·트러블슈팅에서 뽑아 작성) | `type/experience` |
| `-Calendar-/` | 날짜 노트 = 그날의 할 일(TODO)과 겪은 일 (사용자 작성, 경험의 원천). 그래프에서는 Calendar 허브로 묶는다 | `type/journal` |
| `Books/` | 독서 (허브는 예정) | `type/book` |
| `raw/` | 외부 원본 (강의 PDF, 웹 클리핑). 불변이라 읽기만 함. 처음 필요할 때 만든다 | — |
| `Images/` | 첨부 이미지 | — |
| `.wiki/` | `index.md`, `log.md`. 점 폴더라 Obsidian에 보이지 않는다 (LLM 전용) | — |
| `.claude/` | 이 스키마 파일 (`CLAUDE.md`). 점 폴더라 Obsidian에 보이지 않는다 | — |

새 개념 페이지는 가장 가까운 개념 폴더에 만든다. DB·OS·네트워크처럼 특정 폴더가 없는 CS 일반 개념은 `Computer Science/`에 둔다.

### 허브 계층

```
대학생활
├── 학업       → 학기별 과목
├── 전공 지식   → 알고리즘 지도 · 자료구조 지도 · 컴퓨터 시스템 지도 · 네트워크 지도
│                 데이터베이스 지도 · 데이터·AI 지도 · 수학 지도 · 프로그래밍·설계 지도 · 백엔드·인프라 지도
├── 프로젝트    → 프로젝트·활동
├── 경험        → 경험·교훈
└── Calendar    → Calendar 2024 · 2025 · 2026 → 날짜 노트 (자동 생성)
```

- 추가 예정 허브 (사용자가 요청하면 만든다): **독서, 진로·취업, 창업·아이디어, 일상·습관**
- 영역 지도는 과목명과 겹치지 않게 "○○ 지도"로 이름 짓는다. 예: 과목 `알고리즘`과 허브 `알고리즘 지도`는 다른 페이지다.

### 링크 방향 (그래프 모양을 결정한다)

- 허브 → 하위 허브·페이지
- 모든 위키 페이지 → 자기 상위 허브나 지도 1개 이상 (연결 콜아웃의 "상위" 줄)
- 과목 → 그 수업에서 배운 개념
- 프로젝트 → 사용한 개념·기술, 관련 경험
- 경험 → 출처 일지·트러블슈팅, 관련 개념·프로젝트
- 일지 → 거기서 나온 경험·개념·프로젝트 (연결 콜아웃에만)
- Calendar 허브 → 연도 허브 → 날짜 노트. 날짜 노트를 고치지 않고도 그래프에서 한 덩어리로 묶인다.
- `.wiki/`와 `.claude/`는 점 폴더라 Obsidian이 아예 읽지 않는다. 그래서 index의 링크는 그래프나 백링크에 나타나지 않는다.

## 3. 태그 (frontmatter)

기존 규칙(키 순서 `tags → aliases → created`, 기본 태그 `seed`)을 그대로 두고, `tags` 목록에 아래 태그를 추가한다.

- **유형 (정확히 하나)**: `type/hub`, `type/course`, `type/concept`, `type/project`, `type/experience`, `type/journal`, `type/analysis`, `type/book`
- **영역 (개념·분석 페이지에 1개 이상)**: `domain/algorithm`, `domain/data-structure`, `domain/system`, `domain/network`, `domain/database`, `domain/data-ai`, `domain/math`, `domain/programming`, `domain/backend`
- **성숙도**: `seed`(초안) → `growing`(출처 2개 이상을 종합함) → `evergreen`(안정됨). 승격할 때 태그를 교체한다.
- **위키화 여부는 `type/` 태그 유무로 판단한다.** `type/` 태그가 없는 노트는 아직 ingest되지 않은 것(pending)이다.

## 4. 페이지 형식

### 공통: 위키 연결 콜아웃 (문서 맨 끝)

```
> [!info]- 🔗 위키 연결
> - 상위: [[학업]] · [[데이터베이스 지도]]
> - 개념: [[트랜잭션]] · [[DB(DataBase)]]
> - 프로젝트: [[ShoppingMall - 트러블 슈팅 기록]]
> - 경험: [[API 요청 형식 변경은 프론트와 먼저 합의하기]]
> - 출처: [[2026-09-16]]
```

- 쓸 수 있는 줄: 상위, 수업, 개념, 프로젝트, 경험, 출처, 관련, 참고. 해당 없는 줄은 뺀다. 콜아웃이 이미 있으면 새로 만들지 말고 갱신한다.
- AI 에이전트가 계속 뒤에 덧붙이는 파일(예: `copilot-addendum`)은 콜아웃 없이 태그만 단다.
- 헤딩이 아닌 콜아웃을 쓰는 이유는 본문의 교과서식 헤딩 계층을 건드리지 않기 위해서다.

### 과목 (course): 기존 `University/` 노트
- `type/course` 태그를 추가하고 연결 콜아웃을 붙인다. 넣을 줄: 상위(학업, 관련 지도), 개념(이 수업에서 배운 것 중 개념 페이지가 있는 것), 관련 프로젝트·경험.

### 개념 (concept)
- **기존 노트**: 태그와 연결 콜아웃을 붙인다. 넣을 줄: 상위 지도, 배운 곳(과목), 쓰인 곳(프로젝트), 관련 개념.
- **새 개념 페이지는 다음 중 하나일 때만 만든다**:
  1. 2개 이상의 노트에 등장한다.
  2. 영역을 잇는 다리 역할을 한다.
  3. 사용자가 요청했다.

  한 노트에만 나오는 세부 개념은 그 노트 안에 둔다.
- 새 개념 페이지는 RULE_TEXTBOOK_HIERARCHY를 따른다 (`#` → `##` → `###` → `####` + 설명).
- 서술마다 출처 링크를 단다. 출처에 없는 일반 지식으로 보충할 때는 `(보충)`이라고 표시한다.

### 프로젝트 (project)
- 태그와 연결 콜아웃을 붙인다. 넣을 줄: 상위 `[[프로젝트]]`, 사용한 기술·개념, 관련 경험.

### 경험 (experience): `Experience/`의 새 페이지
- 파일명은 교훈이 드러나는 한 문장으로 짓는다. 예: `API 요청 형식 변경은 프론트와 먼저 합의하기.md`

```
---
tags:
  - seed
  - type/experience
aliases: []
created: YYYY-MM-DD
---
# <제목>
## 상황
## 한 일
## 배운 점
## 다음에는
(맨 끝에 위키 연결 콜아웃)
```

- "다음에는" 섹션은 사용자가 앞으로의 다짐을 직접 적었을 때만 쓰고, 아니면 뺀다.
- 사용자가 실제로 쓴 내용만 근거로 한다. 감정이나 평가를 지어내지 않는다. LLM의 해석이 들어가면 `(추정)`이라고 표시하고 사용자에게 확인한다.
- 같은 교훈이 다시 나오면 새 페이지를 만들지 않고 기존 페이지에 사례(출처)를 추가한다. 반복된 횟수가 곧 중요도다.

### 일지 (journal)
- 구조와 문장은 건드리지 않는다.
- frontmatter가 없으면 표준 frontmatter를 추가하고 `type/journal` 태그를 단다. 끝에 연결 콜아웃만 추가한다.

### Calendar 허브 (자동 생성)
- `Hub/Calendar.md`와 `Hub/Calendar <연도>.md`는 `python3 .obsidian-agent/wiki_calendar.py`가 `-Calendar-` 폴더를 읽어 다시 만든다. 손으로 편집하지 않는다.
- 날짜 노트가 새로 생기면 ingest나 lint 때 이 스크립트를 실행한다. 스크립트는 날짜 노트 자체를 수정하지 않는다.
- 연도·월은 폴더가 아니라 파일명(YYYY-MM-DD) 기준이다. 폴더를 잘못 넣은 노트도 제 달에 묶인다.

### 허브 (hub): `Hub/`
- 한두 줄 설명과, 섹션별 하위 페이지 링크 목록으로 구성한다.
- 링크는 반드시 `[[ ]]`로 직접 적는다. Dataview·Bases 쿼리 결과는 그래프에 선을 만들지 않는다.

## 5. 링크 규칙

- Obsidian 위키링크 `[[파일명]]` 또는 `[[파일명|표시 텍스트]]`를 쓴다.
- **파일명이 중복되는 노트는 경로를 포함해 링크한다.** `Algorithm/` 안에 `Merge Sort`, `Quick Sort`, `Binary Search`, `BFS(Breath First Search)`, `DFS(Depth FIrst Search)`, `Dijkstra’s Algorithm`이 두 곳씩 있다. 예: `[[Algorithm/Divide and Conquer Algorithm/Merge Sort|Merge Sort]]`
- 일부 파일명에 굽은 따옴표(`’`)가 들어 있다 (`Dijkstra’s`, `Kruskal’s`, `Prim’s`, `Strassen’s`). 반드시 실제 파일명을 확인하고 링크한다.
- 존재하지 않는 페이지로의 링크는 만들 예정인 개념에만 쓰고, lint에서 추적한다.
- 새 파일명은 한글을 NFC로 저장한다. macOS 밖에서 만든 파일이 NFD로 저장되면 링크가 풀리지 않을 수 있다 (2026-09-25에 `University/2-1`의 5개 파일을 NFC로 정규화함). lint에서 NFD 파일명을 점검한다.

## 6. 작업 절차

### Ingest ("ingest 해줘", "위키에 반영해줘")
대상: 기존 노트(파일·폴더), 일지 기간, `raw/`의 새 자료.
- 사용자가 대상을 콕 집지 않고 "새로 쓴 거 반영해줘"라고 하면: `.wiki/log.md`의 마지막 ingest 날짜 이후 생성·수정된 노트(파일 수정 시각 기준)를 찾아 목록을 먼저 보여주고, 사용자가 고른 것만 처리한다.
- 노트는 사용자가 평소대로 자유롭게 쓴다. ingest는 쓰기 전에 거치는 검사가 아니라, 써 둔 것을 나중에 위키에 엮는 작업이다.

1. 대상을 읽는다. 크면 헤딩 단위로 나눠 읽는다.
2. 핵심 내용과 연결 후보(개념·프로젝트·경험)를 3~7줄로 사용자에게 보여주고 강조점을 확인한다. 사용자가 "알아서 해줘"라고 하면 이 단계를 건너뛰고 한꺼번에 처리한다.
3. 편집할 기존 노트를 백업한다 (안전 규칙 3).
4. 대상 노트를 위키화한다 (태그, 인라인 링크, 연결 콜아웃).
5. 관련 개념 페이지를 갱신하거나 만든다. **틀린 지식이나 페이지 간 모순을 발견하면 본문을 고치지 않고 사용자에게 목록으로 보고한다** (위치, 틀린 내용, 올바른 내용, 근거). 사용자가 승인하면 본문을 고치거나 `> [!warning]` 콜아웃을 단다. LLM이 새로 쓰는 페이지에는 처음부터 올바른 내용만 쓴다.
6. 일지·트러블슈팅에서 경험과 교훈을 뽑아 `Experience/`에 새로 만들거나, 기존 페이지에 사례를 추가한다.
7. 새로 만든 페이지를 해당 허브나 지도에 링크한다.
8. `.wiki/index.md`를 갱신하고 `.wiki/log.md`에 기록한다.
9. 만들고 고친 파일 목록을 사용자에게 보고한다.

### Query (위키에 질문)
1. `.wiki/index.md`에서 시작해 관련 허브와 페이지를 읽고, 필요하면 원문까지 본다.
2. 답에는 근거 페이지 링크를 단다.
3. 비교·분석처럼 다시 쓸 만한 답은 사용자에게 저장 여부를 묻는다. 저장하면 해당 영역 폴더에 `type/analysis` 페이지로 만들고 index와 log를 갱신한다.

### Lint ("점검해줘", 몇 주에 한 번)
다음 항목을 점검한다.
- 페이지 간 모순
- 새 자료 때문에 낡은 서술
- 들어오는 링크가 없는 고아 위키 페이지
- 상위 허브가 없는 페이지
- 여러 번 언급되지만 페이지가 없는 개념
- 깨진 링크
- Calendar 허브에 빠진 날짜 노트 (`wiki_calendar.py` 실행으로 해결)
- 중복 노트 (병합 후보. 병합은 허락받은 뒤에만)
- pending 노트 현황
- `seed` → `growing` 승격 후보
- 복습용 질문 3~5개

결과는 보고만 하고, 수정은 사용자가 확인한 뒤에 한다.

## 7. index.md / log.md 형식

**`.wiki/index.md`**
- 유형별 섹션으로 나눈다: 허브, 과목(학기별), 개념(영역별), 프로젝트, 경험, 분석.
- 항목 형식: `- [[페이지]] — 한 줄 요약`
- 위키화된 페이지만 싣는다. 일지는 싣지 않고, 반영한 기간은 log에 남긴다.

**`.wiki/log.md`**
- 뒤에 덧붙이기만 한다. 형식: `## [YYYY-MM-DD] <종류> | <대상>`, 다음 줄부터 변경 요약 불릿.
- 종류: `setup`, `ingest`, `query`, `lint`, `schema`

## 8. 그래프 뷰

- 색상 그룹은 `.obsidian/graph.json`에 있다 (git 제외). 폴더 기준으로 칠한다: 허브(주황), 학업(파랑), 전공 지식(초록), 프로젝트(보라), 경험(노랑), 일지(회색), 독서(자주).
- 기본 필터는 없다. 위키 관리 파일은 점 폴더(`.wiki/`, `.claude/`)에 있어서 원래 그래프에 나타나지 않는다.
- 보는 순서
  1. 전체 그래프에서 덩어리를 확인한다.
  2. 허브 페이지에서 로컬 그래프(깊이 2)로 영역을 탐색한다.
  3. 태그 필터(type/experience)로 경험 연결망만 본다.
- LLM이 `graph.json`을 수정한 뒤에는 사용자가 명령 팔레트에서 "Reload app without saving"을 실행해야 반영된다.
